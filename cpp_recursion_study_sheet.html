01. What is recursion?

Recursion is when a function solves a problem by calling itself on a smaller version of the same problem.

Everyday analogy

You open a box, find a smaller box inside, and keep opening boxes until you reach the final empty box. Then you work your way back out.

Programming idea

A function keeps calling itself with a smaller input until it reaches a condition where no further call is needed.

void countdown(int n)
{
    if (n == 0)
        return;

    cout << n << endl;
    countdown(n - 1);
}

Calling countdown(3) prints 3, 2, 1. Each call receives a smaller value: 3 → 2 → 1 → 0.

Key idea: Recursion is not an endless loop by definition. It is a sequence of function calls that must eventually reach a stopping condition.

02. The three rules of recursion

1

Base case: the condition that stops further recursive calls.

2

Recursive case: the function calls itself to solve a smaller subproblem.

3

Progress: every call must move closer to the base case.

int sumTo(int n)
{
    if (n == 0)
        return 0;

    return n + sumTo(n - 1);
}
Danger: If the base case is missing—or the input never moves toward it—the function may keep calling itself until the program runs out of stack space.

03. Understanding the call stack

Every function call gets its own stack frame. That frame stores information for that particular call, such as its parameters, local variables, and where execution should continue after the call returns.

The stack follows LIFO: Last In, First Out. The most recently called function finishes first.

void fun(int n)
{
    if (n == 0)
        return;

    cout << "Before " << n << endl;
    fun(n - 1);
    cout << "After " << n << endl;
}

Dry run: fun(3)

CALLING DOWN (new frames are added) fun(3) prints "Before 3" └─ fun(2) prints "Before 2" └─ fun(1) prints "Before 1" └─ fun(0) base case; returns RETURNING UP (frames finish in reverse order) fun(1) resumes → prints "After 1" → finishes fun(2) resumes → prints "After 2" → finishes fun(3) resumes → prints "After 3" → finishes

Output:

Before 3
Before 2
Before 1
After 1
After 2
After 3
The rule: after a recursive call returns, the caller resumes at the statement immediately after that call. The caller's frame has not disappeared yet. It continues through the rest of its function, in order, until it reaches the end or executes a return.

What exactly happens?

1

fun(3) pauses while it waits for fun(2).

2

fun(2) pauses while it waits for fun(1).

3

fun(1) calls fun(0). The base case returns immediately.

4

fun(1) resumes, prints After 1, and finishes. Its frame is removed.

5

fun(2) resumes, then fun(3). Each finishes in turn.

Remember: a recursive call does not erase the caller. It pauses the caller until the deeper call finishes.

04. Print 1 to n vs n to 1

The location of the print statement relative to the recursive call changes the output.

Print before the call

void decreasing(int n)
{
    if (n == 0) return;
    cout << n << " ";
    decreasing(n - 1);
}

For decreasing(4): 4 3 2 1

Print while going down

Print after the call

void increasing(int n)
{
    if (n == 0) return;
    increasing(n - 1);
    cout << n << " ";
}

For increasing(4): 1 2 3 4

Print while returning
Statements before the recursive call run on the way down. Statements after the recursive call run on the way back up.

05. Factorial: returning a value

Factorial means multiplying a positive integer by every positive integer below it. For example, 4! = 4 × 3 × 2 × 1 = 24. By definition, 0! = 1.

int factorial(int n)
{
    if (n == 0)
        return 1;

    return n * factorial(n - 1);
}

Trace factorial(4)

factorial(4) = 4 * factorial(3) waits factorial(3) = 3 * factorial(2) waits factorial(2) = 2 * factorial(1) waits factorial(1) = 1 * factorial(0) waits factorial(0) = 1 base case Now return upward: factorial(1) = 1 * 1 = 1 factorial(2) = 2 * 1 = 2 factorial(3) = 3 * 2 = 6 factorial(4) = 4 * 6 = 24

In n * factorial(n - 1), the function needs the returned value of factorial(n - 1) before it can finish the multiplication.

This is not equivalent to factorial(n - 1); return n;. The recursive result must be used if you want the factorial value.

06. Fibonacci and recursion trees

In the Fibonacci sequence, each number is the sum of the previous two. Here, fib(0) = 0 and fib(1) = 1.

int fib(int n)
{
    if (n <= 1)
        return n;

    return fib(n - 1) + fib(n - 2);
}

Recursion tree for fib(4)

fib(4) / \ fib(3) fib(2) / \ / \ fib(2) fib(1) fib(1) fib(0) / \ fib(1) fib(0) fib(2)=1, fib(3)=2, fib(4)=3.

Each Fibonacci call makes two recursive calls. The same values are recalculated multiple times.

Simple recursive Fibonacci

Easy to understand, but repeated work makes it exponential in time—often given as O(2ⁿ) as a loose upper bound.

Memoization / dynamic programming

Save previously calculated values so each Fibonacci value is computed once. Time can be reduced to O(n).

07. Types of recursion

TypeMeaningExample idea
DirectA function calls itself.f() → f()
Indirect / mutualFunctions call one another in a cycle.f() → g() → f()
TailThe recursive call is the last meaningful operation.Call at the end
HeadThe recursive call happens before the main work.Call first, print after
Multiple / treeA call makes more than one recursive call.Fibonacci
NestedA recursive call is used as an argument to another call of the same function.f(f(n - 1))

These labels describe different properties, so they can overlap. A function can be direct recursion and tail-recursive at the same time.

Tail vs non-tail example

// Tail style
void tail(int n)
{
    if (n == 0) return;
    cout << n << " ";
    tail(n - 1);
}

// Non-tail: work remains after the call returns
void nonTail(int n)
{
    if (n == 0) return;
    nonTail(n - 1);
    cout << n << " ";
}

08. Common recursive array problems

A. Check whether an array is sorted

Compare adjacent elements. If the current pair is out of order, return false. Otherwise, move to the next index.

bool isSorted(int arr[], int n, int i = 0)
{
    if (i >= n - 1)
        return true;

    if (arr[i] > arr[i + 1])
        return false;

    return isSorted(arr, n, i + 1);
}

For {2, 4, 6, 9}, each pair passes and the base case returns true. For {2, 7, 5, 9}, the comparison 7 > 5 returns false.

This version assumes n is non-negative. Empty and one-element arrays are considered sorted.

B. Reverse an array

void reverseArray(int arr[], int left, int right)
{
    if (left >= right)
        return;

    int temp = arr[left];
    arr[left] = arr[right];
    arr[right] = temp;

    reverseArray(arr, left + 1, right - 1);
}

Each call swaps the outside pair and moves both pointers toward the middle.

C. Sum the elements of an array

int sumArray(int arr[], int n)
{
    if (n == 0)
        return 0;

    return arr[n - 1] + sumArray(arr, n - 1);
}

Each call takes the last element of the current prefix and adds it to the sum of the shorter prefix.

09. Recursive binary search

Binary search only works correctly on a sorted array. It checks the middle value and discards half of the remaining search range each time.

int binarySearch(int arr[], int low, int high, int target)
{
    if (low > high)
        return -1;

    int mid = low + (high - low) / 2;

    if (arr[mid] == target)
        return mid;

    if (target < arr[mid])
        return binarySearch(arr, low, mid - 1, target);

    return binarySearch(arr, mid + 1, high, target);
}

Example

Array: {2, 5, 8, 12, 16, 23, 38}, target: 16.

0631216 is larger → search right half
4652316 is smaller → search left half
44416Found at index 4
Base cases: target found → return index. Search range empty (low > high) → return -1.

Complexity: O(log n) time, O(log n) call-stack space in the recursive version.

10. Backtracking: choose, explore, undo

Backtracking explores possible choices. If a choice is finished—or cannot lead to a valid solution—the algorithm reverses that choice and tries another.

1. Choose

Make a temporary decision.

2. Explore

Recursively explore what follows.

3. Undo

Restore state so another choice can be tried.

Example: generate all binary strings of length n

void generate(string& s, int n)
{
    if ((int)s.length() == n)
    {
        cout << s << endl;
        return;
    }

    s += '0';
    generate(s, n);
    s.pop_back();

    s += '1';
    generate(s, n);
    s.pop_back();
}

Call with an empty string and n = 2:

00
01
10
11

The string is passed by reference so recursive calls share the same string. pop_back() removes the last character after each branch, restoring the string to its earlier state.

"" / \ "0" "1" / \ / \ "00" "01" "10" "11"

Where backtracking is used

  • Subsets: include or exclude each element.
  • Permutations: choose one unused element at each position.
  • Maze solving: try a path; undo it if it fails.
  • N-Queens: place queens while checking that each placement is safe.
Common bug: forgetting to undo a choice can contaminate later branches with old state. Undo exactly what you changed, at the correct level.

Time complexity counts the work performed. Space complexity counts extra memory; recursive calls use stack frames. If recursion depth is n, stack space is often O(n).

12. Common mistakes and practice

No base case

Calls never stop.

No progress

Calling f(n) again with the same n can loop through calls forever.

Wrong return

A recursive result is calculated but not returned or used.

Wrong print location

Printing before vs after the call reverses output order.

Wrong binary-search bounds

Use mid - 1 and mid + 1 so the range shrinks.

Forgotten undo

Backtracking branches accidentally share leftover changes.

Practice questions

1. What does a function print if it calls f(n-1) before printing n?

For a base case of n == 0 and a call f(3), it prints 1 2 3. Printing happens during stack unwinding.

2. What is sumTo(4) if sumTo(n) returns n + sumTo(n-1), with sumTo(0)=0?

4 + 3 + 2 + 1 + 0 = 10.

3. Why does binary search need a sorted array?

Comparing with the middle element must tell us which half can safely be discarded.

4. In backtracking, why do we undo a choice?

To restore the state before exploring a different branch.

5. What executes after a recursive call returns?

The caller resumes at the next statement after the call, executes remaining statements in order, and eventually returns or reaches the end of the function.

6. What is the base case for reverseArray(arr, left, right)?

left >= right, because the pointers have met or crossed and there are no more pairs to swap.

How to dry-run any recursive function

1

Write down the first call and its arguments.

2

Mark each statement that runs before the recursive call.

3

Keep expanding calls until the base case is reached.

4

Return to the most recent waiting call and continue after its recursive call.

5

Track returned values separately from printed output. A function can return a value without printing it.

Final self-check: For every recursive solution, ask: (1) What is the base case? (2) How does the input/state change? (3) What happens before the call? (4) What happens after it returns? (5) What does the function return?

Study note: recursion is easier when you trace one call at a time. Follow the calls down to the base case, then unwind them in reverse order.
